# Controlla background click and widget live smoke

Date: 2026-10-14 (local machine)

## Scope and result

This report records isolated fixture checks run through the `controlla4` Hotload MCP. The fixture page had no account or external site state. The user observed that the opened tab was in a browser profile without their account, so this run is **not** evidence about their signed-in Chrome profile, authenticated app behavior, or persistence there. It did not focus or activate that tab.

The run found and fixed two concrete defects:

1. CDP mouse commands to an inactive Chrome tab were acknowledged but did not deliver a click. Controlla previously waited for the full outcome deadline and then returned `unknown`. It now returns a bounded `not_dispatched` receipt before sending input when the selected tab is inactive. The receipt recommends observed-URL background navigation or foreground mode for page controls.
2. The drag/drop verifier looked for retained DOM properties named `source` and `target`, but the hit-test retained `s` and `d`. The drag event reached the fixture target, but exact containment could never be verified. The hit-test now retains the exact nodes under the verifier's expected names and checks both nodes are visible before dispatch.

3. Cold shared opens selected the first stable web tab returned by the extension. That ordering does not identify the intended Chrome window and could bind a new tab to the wrong account profile. The extension now marks the active tab in Chrome's last-focused window; Controlla requires that marker and fails closed when it is missing or ambiguous. This requires reloading the unpacked extension before live qualification.

4. The post-navigation debugger reattach guard also compared a broad navigation counter. A late/duplicate `tabs.onUpdated(status=loading)` notification could increment it after DOMContentLoaded even when the selected URL and committed document ID were unchanged. That caused Controlla to detach an already navigated tab and return `unknown`; the subsequent snapshot then reported `Target is not attached`. The guard now uses route validity, exact URL/document identity, and a pending main-frame navigation record correlated to the committed document ID. A late status-only notification no longer invalidates a stable document. A newer navigation that starts during attach remains blocked, and an old document's delayed DOMContentLoaded cannot clear its pending record. The `document_committed` open mode remains valid before DOMContentLoaded when the committed document ID matches. Pending state is cleaned on matching DOM-ready/error completion, tab removal, or tab replacement.

The shared snapshot selector now includes native and marked draggable elements plus data/ARIA drop targets. Drag preflight resolves nested hit-tested content to its matching draggable/drop-target ancestor and accepts the same native/data/ARIA markers. The browser skill and runtime tool instructions explain the tested inactive-tab limitation consistently. Background click, visual-click, hover, drag, and map-pan paths now check tab activity before expensive work and again immediately before pointer dispatch; an unavailable or malformed activity read fails closed as `not_dispatched`. Chromium can still change activation asynchronously after this check; CDP offers no atomic active-tab-and-input operation.

## Research and benchmark-readiness update

- The [Agent JIT Compilation preprint](https://arxiv.org/abs/2605.21470) reports a 10.4× mean speedup and 28 percentage-point higher accuracy than Browser-Use across five applications, and a 2.4× speedup / 9-point accuracy gain for its scheduler over OpenAI CUA. It attributes most baseline latency to inference and finds materially different costs among valid plans. Its per-application trace/tool synthesis setup takes 25–90 minutes, so the result supports cost-aware compiled execution for repeated tasks, not an instant win for novel tasks or a Controlla result. Controlla already has exact-cohort verified route histories and a compiler path; the evidence still calls for measuring prompt-boundary wall time and cold/warm cohorts separately.
- [CUA-Speedrun](https://arxiv.org/abs/2609.40284) emphasizes a common VM/execution pipeline and controlled task set for speed comparisons. It reports that environment I/O can interact unexpectedly with model reasoning effort, so a browser-only timing or command count cannot stand in for prompt-to-outcome latency. This supports the existing paired, environment-bound Phase 11 gate and argues against claiming superiority from the single ESPN run here.
- [CAP](https://arxiv.org/abs/2608.08392) targets cross-site tasks with complex interactions and perception, with hierarchical diagnosis rather than only final-answer scores. The current 19-class matrix covers that type of breadth but remains unqualified live.
- [The Art of Building Verifiers for Computer Use Agents](https://arxiv.org/abs/2604.06240) focuses on verifier reliability and false positives. The runner's separate verifier and the browser-local identity/postcondition checks are therefore required evidence, not optional overhead to delete for speed.

### Fresh audit correction: background activity wire shape

The fresh full-diff review found that this report's earlier statement that the current candidate's activity guard was validated was too strong. The extension returns `Controlla.presentationState` as a direct `{tab_active, window_focused, ...}` object; the provider unwraps the extension envelope before returning from `command`. The new Rust guard incorrectly tried to parse that object as a CDP `{result:{value:...}}` wrapper. That means actual candidate background pointer paths would fail closed as `background_activity_unavailable`, even when the tab was active. The existing test only exercised the synthetic CDP wrapper and missed the real wire shape. Prior live observations are not evidence that this uncommitted guard worked.

The current source now accepts the direct provider result, the full extension envelope, and the existing CDP wrapper, while requiring both activity flags to be booleans. All three raw presentation-state call sites use the same normalizer. A regression test first failed on the actual direct result shape, then passed after the fix; it also checks an inactive full provider envelope maps to `inactive_background_tab`. At the time this correction was first recorded, the remaining gates were still pending. The following section records their final results.
