# Live client smoke adapters

`npm run check:clients` validates configuration and the smoke evidence contract. Six named MCP adapters map Freebuff, OpenCode, Claude Code, Codex, ChatGPT Desktop, and generic MCP to their checked-in integration configs. `npm run smoke:client-mcp-contracts` launches each configured MCP endpoint, performs initialize and tools/list, verifies the pinned six-tool schema fingerprint, and writes a report explicitly marked `contract_only` / `qualification_status: not_run`. Set `CONTROLLA_BINARY_PATH` to an absolute built Controlla binary first. `npm run check:client-hosts` reports whether each actual client host is runnable in this environment; it never upgrades host availability into a qualification result.

`scripts/client-host-adapters.mjs` prepares isolated non-interactive launch configurations for Codex, OpenCode, and Claude Code, then runs bounded host prompts while recording MCP tool-call events and an output hash. It disables unrelated tools in OpenCode and uses strict MCP configuration for Claude Code. Freebuff is classified interactive-only because its CLI has no prompt mode; ChatGPT Desktop requires an in-app driver; generic MCP is protocol-only. Missing executables are reported explicitly. Host launch and tool-call observations are not behavior qualification.

Behavioral live-client qualification remains a separate command: `npm run smoke:clients`. It accepts per-client evidence-driver argv from `CONTROLLA_CLIENT_SMOKE_COMMANDS_JSON` and three host-task prompts per runnable CLI from `CONTROLLA_CLIENT_HOST_TASKS_JSON`, keyed by client ID with `read_only`, `verified_mutation`, and `mode_specific` strings. The public runner now launches Codex, OpenCode, or Claude Code itself, requires actual Controlla tool-call events for each task, requires the mutation run to call both `act` and `verify`, and requires the mode run to call `browser open` with `background` or `headless`. The evidence driver receives the observed host process IDs, exact tool-call events, output hashes, and isolated MCP configuration; it must return those same observations in both its result and evidence file. Its independent mutation observer is still required by the evidence validator. Missing client binaries, credentials, prompts, or evidence drivers fail before any qualification result is written. Interactive-only clients require their own registered in-app driver.

The runner resolves the matrix's checked-in integration config for that exact client before dispatch. It rewrites the Controlla executable to `CONTROLLA_BINARY_PATH`, assigns a unique state directory per client/run, pins the six-tool `v3-compact` surface, and sends the evidence driver the normalized launch context, client and host identity, fresh `run_id`, start time, required capabilities, and actual host task observations. The driver returns one JSON result with the same run ID, client and Controlla versions, an absolute evidence path, its SHA-256, verified capabilities, and the exact observed host process/tool-call/output-hash bindings. The evidence file must repeat those host bindings and include one live, passed case per required capability. Each case includes an observer, an `observed_at` timestamp inside the current run window, and proof. Mutation cases must include a verified action receipt and a distinct independent observer.

The runner verifies process output, evidence-file hash, run/version binding, resolved integration-config hash, timestamps, exact six-tool schema, capability-specific proof fields, capability coverage, and independent mutation-observer identity. Synthetic fixture markers are rejected by the live CLI. Each real adapter must attach to or launch its named client in an isolated test configuration, and must provide observed evidence for session reuse, foreground/background/headless operation, blocked/fast/human/IME typing, multi-tab work, user interference, upload/download, sourced extraction, and independently verified mutation. Config resolution and MCP launch context are implemented for all six checked-in integrations; client driver commands and client-local credentials remain explicit per-client inputs. Missing binaries, drivers, or credentials fail with an actionable error and cannot produce a qualification record. `scripts/test-fixtures/client-smoke-adapter.mjs` exists only to test orchestration in a temporary directory. Its synthetic output cannot be used to set `liveSmokeStatus` or make a compatibility claim. Production compatibility requires freshly collected, client-owned live observations.
