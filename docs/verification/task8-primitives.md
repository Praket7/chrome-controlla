# Task 8 primitive route, 2026-10-09

Status: implemented in the V3 MCP binary with focused fixture and installed-Chrome headless coverage. Authenticated school/work application persistence remains unqualified.

The `browser` tool's `action=task` route expands bounded research, form draft, and repeat requests into existing guarded browser operations. Research visits up to 32 caller-supplied HTTP(S) URLs, optionally assigning each URL to one explicitly paired tab ID, checks the observed URL after each navigation, and extracts up to 100 text items per page with a 2,000-character receipt. Form drafts reobserve before each fill, verify the field value afterward, and require an explicit save control and visible confirmation before clicking Save. The guarded click route rejects submit controls. Repeat clicks require a declared outcome; unknown or failed outcomes stop the sequence. Receipts exclude full snapshots and field values.

`browser` actions `artifact_register` and `artifact_read` stage at most 10 MiB of caller-provided bytes under an opaque handle in a dedicated private headless session. The upload primitive checks a caller-declared account marker before and after selecting the artifact through the existing guarded CDP file-input API. A successful selection returns `incomplete`: Chrome readback establishes the selected filename and size, while application transfer and persistence remain unverified. For downloads, Chrome writes into a bounded directory inside its private temporary profile. The runtime matches the begin/completion events to the selected frame and GUID, checks a regular file and byte count, computes SHA-256, and stages the verified bytes behind an opaque handle returned in the receipt. `artifact_read` returns the bytes to the owning session. Shared-profile file operations fail before dispatch. No request accepts an arbitrary filesystem path.

Focused evidence: `cargo test -p controlla-runtime --locked --offline --test v2_stdio --test v3_tasks` passed (10 default tests). Two installed-Chrome tests passed when explicitly enabled: one verified a downloaded export and `artifact_read` byte readback, then staged and selected an upload with an account marker; the other visited two local HTTP sources, captured cited snippets, filled and saved a draft with a visible confirmation, and checked repeated controls. The unit expansion test covers 10 distinct paired tab IDs. These tests do not establish behavior on authenticated apps or prove uploaded-file acceptance or saved-state persistence after reopening.
