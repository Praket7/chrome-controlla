# Controlla 40-improvement implementation and reconciliation plan

Source: user-provided attachment “Pasted text.txt” (40 requirements). The full item text below is the acceptance scope.

## Intent and constraints

Make the current Controlla checkout faster and more reliable for coding agents through one-call deterministic programs, browser-local guarded execution, event-driven target state, compact grounding, durable artifacts/checkpoints, and measured routing. Keep context-sensitive reasoning with the agent. Never weaken fresh identity, independent verification, mutation serialization, unknown-effect no-retry, account binding, or secure password handling. User-supplied passwords remain one-shot secure-fill values and must never enter cache, logs, snapshots, traces, metrics, or persisted task state.

## Execution sequence

1. Map current code and evidence to every requirement; mark existing implementation, code gap, and environment-only evidence separately.
2. Implement shared contracts and browser-local/event-driven architecture before caller-facing routing and replay.
3. Optimize observations, refs, recovery, artifacts, concurrency, and long-task state using existing proven abstractions.
4. Slim and stabilize model-facing contracts; add SLO and matched-benchmark gates.
5. Run red-green tests and local smoke/contract/release checks; do not represent fixture results as live qualification.
6. Reread all 40 source items and reconcile each against code, tests, and remaining environment evidence.

## Requirements

- [ ] **01** P0 — Make TaskCapsule the primary execution architecture. Needed: one request should contain target selection, observation requirements, actions, branching, verification, extraction, and artifact handling, then execute locally without returning to the model between obvious steps. Your Stage 3 plan describes this direction but it is not yet the universal fast path.  Benefit: biggest possible reduction in SEND → finished latency, model turns, MCP calls, and opportunities for the agent to make intermediate mistakes.
- [ ] **02** P0 — Move the hot loop completely browser-side. Needed: after receiving a TaskCapsule, the extension/native runtime should perform observe → resolve → act → verify → continue itself. Do not bounce every identity read, interaction epoch, geometry check, CDP call, and verification across Rust ↔ native messaging ↔ service worker individually. Benefit: a normal click should not take ~17 internal round trips and a trivial navigate/extract task should not take 31. This is probably the single largest raw execution-speed win.
- [ ] **03** P0 — Target ≤3–4 host round trips for ordinary actions. Combine document identity, loader, interaction epoch, geometry, target revalidation, actionability and relevant frame information into one preflight envelope. Dispatch once. Perform one event-driven postcondition/readback. Your current optimization plan already recognizes redundant guarded reads, but its implementation is incomplete.  Benefit: clicks, fills, scrolls and drags become near-native CDP speed without giving up Controlla's safety checks.
- [ ] **04** P0 — Build a persistent event-driven “Watcher State Mirror.” Maintain a live versioned browser graph from Chrome events containing windowId → groupId → tabId → targetId → frame/document/loader → URL → focus/activity → interaction revision. Actions consume an expected revision rather than re-querying the entire browser. Benefit: virtually eliminates repetitive discovery polling, instantly detects navigation or user interference, and lets Controlla adapt without interrupting execution.
- [ ] **05** P0 — Make tab groups and windows first-class identities. Add durable selectors such as group_id, window_id, tab_id, group title, target ID, opener ID, account/profile fingerprint and document revision. Watch chrome.tabGroups, tabs, windows, and CDP Target events continuously. Benefit: the watcher can say “work only in this Chrome window/group” and Controlla can keep operating there even as tabs move, reorder, navigate, open popups, or reload.
- [ ] **06** P0 — Persistent target binding instead of rediscovery. session + tab should resolve directly to a warm CDP attachment until Chrome proves it invalid. agent-browser recently added persistent session-to-target binding specifically for this reason. Benefit: commands stop paying tab enumeration, matching and attachment overhead over and over.
- [ ] **07** P0 — Add a safe browser-local program/batch executor. Not giant task-specific “tools.” Give the agent a small deterministic DSL such as find, click, fill, press, scroll, waitFor, extract, download, assert, if, bounded forEach, and parallel read operations. Stagehand's current run/batch approach demonstrates why this architecture is fast. Benefit: one model decision can cause 5–30 browser operations while still remaining inspectable, bounded and verifiable.
- [ ] **08** P0 — Keep reasoning outside reusable tools. The 2026 Tool Illusion study found overly complicated task-specific tools can actually reduce performance and raise token/action overhead. Deterministic reusable UI operations should be compiled. Context-sensitive planning should remain with the agent. Benefit: you get batching speed without creating hundreds of brittle website macros.
- [ ] **09** P0 — Replace full observations with revision-based semantic deltas. A snapshot should normally return only newly appeared, removed, changed and task-relevant nodes since revision N. Include a full snapshot only when requested or after invalidation. Your earlier Canva path produced roughly 128 KB of observation data, which is exactly the kind of overhead current research says to eliminate. Benefit: enormous token reduction, less model distraction, lower TTFT and faster grounding.
- [ ] **10** P0 — Make compact AX/DOM the default and vision an escalation. First use interactive accessibility nodes plus relevant text and links. Escalate to a cropped screenshot only for canvas, maps, ambiguous geometry, visual state, charts or failed semantic grounding. Current research consistently supports selective reading rather than ingesting the whole page every turn. Benefit: Stagehand/agent-browser-level context efficiency without losing Controlla's stronger visual abilities.
- [ ] **11** P0 — Create unified durable element refs. Each ref should fuse document revision + frame path + backendNodeId + AX identity + role/name + selector hints + geometry + visual fingerprint. Reacquisition should score all those signals. Benefit: refs survive minor React rerenders and layout shifts instead of forcing another model observation.
- [ ] **12** P0 — Local self-healing before model re-grounding. When a ref goes stale, try backend node recovery, exact role/name, labels, DOM ancestry, nearby text, structural signature and geometry locally. Only ask the model after those fail. Benefit: dramatically fewer screenshot/snapshot/model loops on dynamic applications.
- [ ] **13** P0 — Finish verified replay and expand it far beyond extraction. Your newest commit added a verified non-secret replay cache, which is the right direction, but currently replay is still narrow.  Extend it to navigation routes, search, common button selection, forms, downloads, filtering, editor actions and safe composed routines. Require fresh structure/document checks before replay. Benefit: repeated workflows approach deterministic automation speed with zero new grounding.
- [ ] **14** P0 — Learn “skills,” not giant site scripts. Store short polymorphic operations that usually replace roughly 2–5 primitive GUI steps. Parameterize values and reacquire live targets every execution. Benefit: the system gets faster with use while remaining resilient to UI changes instead of accumulating fragile recordings.
- [ ] **15** P0 — Make response compaction goal-aware, not byte-aware. The earlier competitor pilot actually executed the task but failed because compaction dropped the requested title/paragraph. The subsequent commit fixed this.   Formalize a required_outputs contract so requested answer fields, evidence and postconditions can never be discarded before diagnostics. Benefit: prevents false task failures while keeping responses tiny.
- [ ] **16** P0 — Ship a slimmer model-facing tool catalog. Internally keep your six-tool compatibility API, but default agents to roughly 3 concepts such as run, observe, and artifact. Your current skill has to teach substantial routing logic across six tools and many special cases.  Benefit: smaller tool schemas, fewer wrong tool selections, fewer prompt tokens and less agent hesitation.
- [ ] **17** P0 — Automatically infer mode and provider. The model should almost never reason about foreground/background/headless mechanics. Given the target and requested operation, a local capability router should choose the fastest qualified execution provider. Benefit: fewer arguments, fewer failures and easier use by weaker/faster models.
- [ ] **18** P0 — Turn the execution-cost router into a learned empirical router. Track success rate, p50/p95 latency, internal commands, observation bytes, stale-ref rate, false-success rate and focus interference for each (site family, operation, mode, provider). Pick the Pareto-best qualified route automatically. Benefit: Controlla continuously becomes faster based on real performance rather than hard-coded heuristics.
- [ ] **19** P1 — True background visual automation. Complete and qualify compositor screenshots, semantic interactions and target-addressed CDP input for inactive same-window tabs, unfocused windows, covered windows and minimized automation windows wherever Chrome allows it. Benefit: the user keeps working normally while Controlla sees and operates another browser surface.
- [ ] **20** P1 — Treat background screenshots as state objects, not pictures. Return screenshot revision, document identity, viewport/scroll coordinates, dimensions, DPR, render timestamp and hash. Attach actionable refs/boxes when requested. Benefit: an agent can screenshot in the background and immediately make a causally safe action from that exact visual state.
- [ ] **21** P1 — Add render-stability gating. Before a visual decision, wait intelligently on navigation/lifecycle events plus bounded animation/layout stability rather than fixed sleeps. Use app-specific stability only where required. Benefit: fewer clicks based on half-rendered pages without slowing every normal page.
- [ ] **22** P1 — Build a complete drag engine. Support native mouse drag, touch drag, HTML5 DataTransfer, cross-frame coordinate transformation, sliders, reorderable lists, canvas dragging and file-drop targets, with postcondition verification. Benefit: closes one of the remaining gaps between “browser automation” and genuine computer use.
- [ ] **23** P1 — Make uploads one primitive end-to-end. upload(handle, target, expected_acceptance) should mount/reveal the input if needed, set files, watch DOM/network/app state and return separate selected, accepted, and persisted proofs. Benefit: eliminates the huge sequence of discovery and verification operations that historically made upload one of Controlla's most expensive paths.
- [ ] **24** P1 — Make downloads first-class event streams. Watch Chrome download events, correlate them to the initiating action, preserve filename/MIME/size/hash/source identity and return an opaque artifact handle immediately. Benefit: reliable signed-in downloads and no polling filesystem state.
- [ ] **25** P1 — Add a zero-copy artifact workspace. Screenshots, downloaded PDFs, CSVs, images and uploads should stay behind handles inside the runtime. A downloaded artifact should be uploadable in the next action without shipping its bytes through the model or MCP. Benefit: very fast research/document workflows and dramatically lower context usage.
- [ ] **26** P1 — Parallelize independent research at the browser level. A Research capsule should be able to open 4–8 background tabs, perform read-only navigation/extraction concurrently, then aggregate results. Mutations remain serialized per target. Benefit: turns Controlla into an actual “second brain” for research instead of a sequential browser robot.
- [ ] **27** P1 — Add explicit task DAG execution. Allow dependencies such as search → parallel open results → extract → filter → download top papers → verify. Execute independent nodes concurrently. Benefit: long assignments can complete much faster without requiring a model round trip between every page.
- [ ] **28** P1 — Human/agent cooperative scheduling. Detect real user pointer/keyboard/navigation events. If the user touches the same target, expire the mutation lease and rebase. Read-only tasks on unrelated tabs can continue. Benefit: genuine uninterrupted coexistence instead of either stealing control or aborting the whole job.
- [ ] **29** P1 — Use mutation leases, not session-wide locks. Lock only the exact document/target during a short critical interaction. Keep other tabs and read operations concurrent. Benefit: higher throughput while maintaining protection against human/agent races.
- [ ] **30** P1 — Externalize long-task state. Keep concise task state, artifacts, extracted facts, checkpoints and unresolved requirements outside the model context. Research from AgentFold, WebCoach and InfiAgent strongly supports bounded active context plus persistent external state. Benefit: assignments and deep research can run for dozens or hundreds of actions without context degradation.
- [ ] **31** P1 — Resume from semantic checkpoints. Checkpoints should describe goal progress, verified facts, current targets, artifacts and pending work rather than raw trajectory history. Benefit: Chrome/service-worker/model interruptions do not force the agent to rediscover everything.
- [ ] **32** P1 — Eliminate the monolithic execution core. Break mcp/v3_full.rs, mcp.rs, and the huge extension background implementation into generated command contracts plus independent modules for target management, perception, input, files, verification, workflows and transport. Benefit: fewer contract mismatches, duplicated guards and regressions, and much faster optimization work.
- [ ] **33** P1 — One generated protocol definition across Rust and JS. Generate request/response validators, enums, limits and capability declarations from one schema. Benefit: prevents bugs like one side accepting an option while the extension rejects it.
- [ ] **34** P1 — Make MV3 restarts invisible. Keep authoritative warm state in the native runtime, reconstruct extension/CDP bindings from Chrome target events after service-worker wake, and persist only the minimum safe session metadata needed. No permanent heartbeat required. Benefit: watcher automation stops feeling interrupted by extension lifecycle behavior.
- [ ] **35** P1 — Network-aware read acceleration. For research/extraction, detect first-party JSON/XHR/GraphQL responses and use their already-loaded structured data when that is safer and cheaper than traversing thousands of DOM nodes. Benefit: instant extraction on many modern applications while preserving the real logged-in Chrome session.
- [ ] **36** P1 — Visual probing instead of full vision. On ambiguous UIs, ask the runtime for a targeted crop or region around candidate controls rather than the entire screenshot. Recent browser-agent research specifically points toward active/local visual probing. Benefit: retains vision accuracy with a fraction of the visual-token cost.
- [ ] **37** P2 — Automatic capability induction. When Controlla repeatedly succeeds at the same deterministic operation, propose a reusable parameterized skill, test it against structural variations, then qualify it. Benefit: the browser layer improves over time instead of paying the same exploration cost forever.
- [ ] **38** P2 — Site-provided WebMCP/API actions should be opportunistic only. Use them when qualified, but never flood the model with hundreds of site tools. The 2026 tool-use research found large libraries can increase both action overhead and tokens. Benefit: API-level speed where available without recreating the “tool explosion” problem.
- [ ] **39** P2 — Add per-operation latency SLOs. Example warm targets: semantic click <50 ms runtime, fill <40 ms, scroll <40 ms, snapshot delta <50 ms, background screenshot <100 ms, known replay workflow <150 ms excluding page/network time. Benefit: optimizations become measurable engineering targets instead of subjective “feels faster.”
- [ ] **40** P2 — Make the full competitive matrix the release gate. Your current report explicitly says the six-adapter pilot is not enough to support a superiority claim.  Run matched tasks against Stagehand, Browser Use, agent-browser, Playwright MCP and Chrome DevTools MCP with ≥30 repetitions, p50/p95, exact success, input tokens, tool/model turns, host/CDP calls and focus violations. Benefit: you will know exactly where Controlla loses and can prevent regressions.
