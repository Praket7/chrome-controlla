## Phase 6 boundary

- Workflow MCP admission starts a durable job and returns its operation ID; `workflow_status` retrieves persisted revisions and latest checkpoints under a 60-second deadline. Browser operations are claimed/countable before dispatch and timeouts retain unknown delivery. Client disconnect does not cancel an accepted job, and there is no workflow-cancel tool. At process startup, accepted and running/not-sent jobs fail as not sent; jobs past the dispatch claim become unknown while preserving observed delivery and the latest checkpoint. Chrome sessions are not rehydrated and interrupted jobs are not resumed.
- The stdio server takes an exclusive OS file lock on its state directory before opening or recovering the journal and holds it for the server lifetime. Concurrent MCP clients must use distinct directories, for example `CONTROLLA_STATE_DIR="$HOME/.chrome-controlla/client-a" controlla mcp` and `CONTROLLA_STATE_DIR="$HOME/.chrome-controlla/client-b" controlla mcp`; PowerShell can set `$env:CONTROLLA_STATE_DIR` to a distinct path before each server launch. A duplicate owner exits before journal recovery with an actionable error. Phase 9 generates isolated client examples; they still need validation in real clients.
- The pinned `rquickjs 0.14.0` worker is only enabled by `CHROME_CONTROLLA_ENABLE_TRUSTED_SCRIPTS=1`. It now runs in a bounded child process with cleared environment and brokered observe calls; the parent rechecks authority per call and kills the child on deadline. QuickJS heap/stack, source, output, and operation limits are tested. This is not a kernel sandbox or an OS RSS/CPU quota. Untrusted and production scripts stay blocked pending hard OS resource controls, disconnect-cancellation semantics, and platform qualification. `node:vm` is not used as a security boundary.
- Trusted local scripts can perform bounded observation and return one inline artifact using {kind:"artifact",filename,media_type,bytes:[...]}. The runtime rejects unknown fields, unsafe basenames, non-allowlisted media types, empty or over-12-KiB bytes, and out-of-range byte values. Bytes and SHA-256 are stored in the durable operation receipt with operation/principal/session identity and retrieved through `workflow_status`; no filesystem path or download handle is created. The child worker remains unqualified as an OS security boundary, so scripts stay default-off and limited to trusted local use. Dependency-scoped invalidation and effect-aware splitting exist as deterministic planning rules; the Phase 6 fixture comparison reports operation/recovery counts only. Arbitrary mutation integration, file-backed/download artifacts, measured browser overhead, and wall-clock profiling remain open.
