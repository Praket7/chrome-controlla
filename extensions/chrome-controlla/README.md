# Chrome Controlla Shared Tab Bridge

This unpacked Manifest V3 extension pairs only explicitly selected Chrome tabs. One-time setup: load this directory from `chrome://extensions` using **Load unpacked**, copy the exact extension ID displayed there, run `controlla install-bridge <that-id>`, then reload the extension. The extension ID varies by installation and must not be copied from an example. Chrome native messaging is the default; it requires no remote debugging port and no manual endpoint or token entry. The popup's WebSocket fields are a manual fallback only when the native host is unavailable or busy.

Shared-session target identifiers are decimal Chrome `tabs.Tab.id` values. They are a different identity namespace from CDP target IDs used by dedicated direct-CDP sessions. The Rust provider checks exact selected-tab membership and rechecks the live session grant before every command. `Browser.*` and `Target.*` commands are rejected; direct CDP dispatch is not used for shared mode.

For native MCP pairing, call `discover_shared_tabs`, select exact decimal IDs from `snapshot.tabs`, and pass both `snapshot.host_id` and those `target_ids` to `pair_shared`. An early `accept_shared` returns `accepted: false` while the extension is connecting. Without `host_id`, `pair_shared` uses the manual popup fallback. Discovery lists at most 100 eligible tabs; if `snapshot.truncated` is `true`, later tabs were omitted. Pairing trusts the MCP client that supplies the IDs. Chrome's debugger indicator appears for attached tabs; separate browser-side per-tab approval beyond that indicator is not established. This route uses the extension's `chrome.debugger` permission; it does not require Chrome DevTools remote debugging to be enabled. Then call `list_shared_targets`, `shared_observe`, or `shared_accessibility` with one selected `chrome_tab_id`. `shared_accessibility` reads one selected AX node with an overall deadline and bounded response. `shared_input` supports guarded fill, sequential nonempty ASCII typing, and unobstructed click. Typing requires one visible ordinary text input or textarea, the exact current value, focus, and a collapsed caret at the end. It retains a CDP handle to the original DOM element, confirms the unique selector still resolves to that same object around each key event, retries key release at most once, and verifies final DOM value/caret on that same object. Any uncertain key or key-release acknowledgement returns an error even when cleanup succeeds. Fill and typing return DOM readback only. Click refreshes the hit test immediately before dispatch and requires a separate element whose exact observed value changes. Its overall deadline is 6–60 seconds. A page can still change in the small gap between validation and Chrome dispatch; if dispatch or key/mouse release is uncertain, stop using that target and reobserve. It checks root frame ID, loader ID, and URL before and after, but does not prove app acceptance, save, or persistence. It is not qualified for Slides, Canva, CapCut, rich editors, or masked/trusted controls. Use `release_shared` to detach. Shared targets do not expose Direct CDP `TargetRef` values or navigation epochs.

The host accepts one native session at a time; that session may include multiple tabs. For the manual fallback, omit `host_id`, use the endpoint and one-session token returned by `pair_shared` in the popup, then call `accept_shared`. Closing the provider or native connection detaches its tabs.

Fixture tests cover authentication, selected-tab binding, command routing, and grant revocation. Live checks verified Chrome launching the registered host and MCP reading its fresh tab inventory. A separate popup-based session completed one bounded live read-only observation. Native-route tab attachment and commands, writes, app acceptance/persistence, browser-version coverage, and platform-specific focus/foreground behavior remain unqualified. The extension uses Chrome's debugger permission and indicator; separate browser-side approval for each tab is not established.
