# Chrome Controlla Shared Tab Bridge

This unpacked Manifest V3 extension pairs only explicitly selected Chrome tabs. It binds discovery and initial attachment to Chrome's `webNavigation` document IDs, then refreshes that identity when the same selected tab commits an HTTP(S) navigation. Commands pause during navigation; failed or unsupported navigations detach the tab. Chrome 106 or later is required. From the repository root, build with `cargo build --locked --release -p controlla-runtime`. In `chrome://extensions`, enable Developer mode and use **Load unpacked** to load this directory; approve the `webNavigation` permission if Chrome prompts. Copy the exact 32-character extension ID shown on the extension card, then register the native host with the built executable's absolute path: `"$PWD/target/release/controlla" install-bridge YOUR_EXTENSION_ID` (on Windows use the absolute `target/release/controlla.exe` path). The native-host manifest records that executable path and allows only the loaded extension origin. Reload the extension after registration, then configure the MCP client to run the same executable with argument `mcp`. The extension ID varies by installation and must not be copied from an example. Chrome native messaging is the default; it requires no remote debugging port and no manual endpoint or token entry. The popup's WebSocket fields are a manual fallback only when the native host is unavailable or busy. Full local MCP config examples are in [`../../docs/clients.md`](../../docs/clients.md).

Shared-session target identifiers are decimal Chrome `tabs.Tab.id` values. They are a different identity namespace from CDP target IDs used by dedicated direct-CDP sessions. The Rust provider checks exact selected-tab membership and rechecks the live session grant before every command. `Browser.*` and `Target.*` commands are rejected; direct CDP dispatch is not used for shared mode.

For native MCP pairing, call `discover_shared_tabs`, select exact decimal IDs from `snapshot.tabs`, and pass both `snapshot.host_id` and those `target_ids` to `pair_shared`. An early `accept_shared` returns `accepted: false` while the extension is connecting. Without `host_id`, `pair_shared` uses the manual popup fallback. Discovery lists at most 100 eligible tabs; if `snapshot.truncated` is `true`, later tabs were omitted. Pairing trusts the MCP client that supplies the IDs. Chrome's debugger indicator appears for attached tabs; separate browser-side per-tab approval beyond that indicator is not established. This route uses the extension's `chrome.debugger` permission; it does not require Chrome DevTools remote debugging to be enabled. Then call `list_shared_targets`, `shared_observe`, or `shared_accessibility` with one selected `chrome_tab_id`. `shared_accessibility` reads one selected AX node with an overall deadline and bounded response. `shared_input` supports guarded fill, sequential nonempty ASCII typing, and unobstructed click. Typing requires one visible ordinary text input or textarea, the exact current value, focus, and a collapsed caret at the end. It retains a CDP handle to the original DOM element, confirms the unique selector still resolves to that same object around each key event, retries key release at most once, and verifies final DOM value/caret on that same object. Any uncertain key or key-release acknowledgement returns an error even when cleanup succeeds. Fill and typing require unchanged root frame, loader, and URL. Click refreshes the hit test immediately before dispatch; when it navigates, it returns success only after the new document is observed in the same selected tab. Its overall deadline is 6–60 seconds. If dispatch or key/mouse release is uncertain, stop using that target and reobserve. These checks do not prove app acceptance, save, or persistence. Shared input is not qualified for Slides, Canva, CapCut, rich editors, or masked/trusted controls. Use `release_shared` to detach. Shared targets do not expose Direct CDP `TargetRef` values or navigation epochs.

## Diagnosing a shared-command timeout

Open `chrome://extensions`, find **Chrome Controlla Shared Tab Bridge**, and click **Inspect** under its service worker. In the DevTools Console, enable Verbose messages and retry one read-only MCP command. The service worker emits bounded `dispatch`, `settled`, and `reply` records correlated by command ID. A lone `dispatch` means Chrome's debugger Promise has not settled; `settled` without a sent `reply` points to extension/native forwarding; `reply` with `outcome: "sent"` means Chrome accepted the extension's native-port `postMessage`, but does not prove the native host or MCP received it. The records omit page content, URLs, command parameters, tokens, and error bodies. Do not use this trace to infer a browser write outcome.

The host accepts one native session at a time; that session may include multiple tabs. For the manual fallback, omit `host_id`, use the endpoint and one-session token returned by `pair_shared` in the popup, then call `accept_shared`. Closing the provider or native connection detaches its tabs.

After acceptance, `shared_tab` supports `action:"open"` with `url` to create an active tab in the same session, and `action:"navigate"` with the exact `chrome_tab_id` and destination `url`. URLs must be HTTP(S), at most 2048 characters, and contain no credentials. Both actions return the tab ID, final URL, and fresh document ID. A navigation failure may leave its target detached; rediscover and pair again before using it.

Fixture tests cover authentication, selected-tab binding, command routing, and grant revocation. On 2026-10-09, the current native route paired an explicitly selected local fixture tab, completed guarded fill/type/click and mock in-memory post actions, invalidated the session after navigation, re-paired, read the new document, and released/closed the fixture. A file-input attempt was blocked and no file was uploaded. This verifies only the disposable fixture, not real app acceptance or persistence. Classroom writes, app acceptance/persistence, browser-version coverage, and platform-specific focus/foreground behavior remain unqualified. The extension uses Chrome's debugger permission and indicator; separate browser-side approval for each tab is not established.
